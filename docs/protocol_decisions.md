# Protocol V1.2.0 frozen decisions

- Package: `codex.remote.v1`; Go import: `github.com/FireflyTang/codex-remote-protocol/gen/go/codex/remote/v1` from [codex-remote-protocol](https://github.com/FireflyTang/codex-remote-protocol) exact `v1.2.0`. The exact tag, peeled source commit, and descriptor hash are pinned in the Host root [`protocol.lock`](../protocol.lock).
- Transport: one ProtoJSON `Frame` per UTF-8 WebSocket text message, subprotocol `codex-remote.v1.protojson`.
- Endpoint: embedded `tsnet.Server.Listen("tcp", ":80")` at Tailnet-only `ws://<tsnet-node>/connect`; no WSS, `ListenTLS`, Serve, Funnel, host-network or public fallback.
- Version: ClientHello and ServerHello use exact `{major:1, minor:2, patch:0}`. Missing or any other component closes with `CLOSE_CODE_PROTOCOL_VERSION_UNSUPPORTED`; there is no compatibility fallback.
- RPCs: the Host supports all 24 V1.2.0 request variants: 22 backend RPCs plus connection-scoped WatchCodex and UnwatchCodex. The additions are UploadImageAttachment and DownloadImageAttachment.
- Events: the Host produces all 10 V1.2.0 event families: CodexUpdated, CodexForgotten, TurnUpdated, ItemStarted, ItemDelta, ItemUpdated, ItemCompleted, PendingRequestUpdated, WarningRaised, and WorkspaceAccessStateUpdated.
- Image attachments: `Capabilities.image_attachments` advertises PNG, JPEG, and GIF; default upload capacity is 2 MiB or half the configured formal frame, whichever is smaller, and `unreferenced_retention_ms` is 24 hours. Retention is a minimum: this Host implements no attachment GC and retains uploads indefinitely.
- Attachment identity: immutable attachment descriptors belong to a Host-persisted logical session owner independent of `codex_id`, CWD, and the current native thread ID. Ownership survives restart, Unmanage, Forget/re-import, and replacement of an unmaterialized native thread. `StartTurn` preserves ordered text/image parts, resolves images to private `localImage` paths for app-server, and publishes descriptors—not paths—in realtime and history.
- Workspace: `Capabilities.workspace` is present with five strictly positive enforced limits. With the default 4 MiB frame they are 512 KiB text, 2 MiB inline upload, 2 MiB inline download, 32 MiB expanded archive data, and 1,000 archive entries; inline/text limits are reduced for smaller configured frames. Management state does not gate workspace access, including for `UNMANAGED` Codexes.
- Workspace mutation: GetWorkspace, RESET CurrentView, and WorkspaceAccessStateUpdated expose the same generation-based state. `generation` is persisted and monotonic; `active_agent_count` includes the parent and every subagent; a fresh opaque `quiescence_token` is required for mutation. Write/upload are rejected until all agents stop, while list/read/download remain available. Revisions are nonempty only for regular files; Upload is token-gated unconditional create-or-replace (regular/directory cross-kind replacement allowed), while WriteText remains CAS.
- Completeness: `Completeness` is the common contract for truncated bytes and incomplete sources/collections. It is attached at Event, item, turn, session candidate, CurrentView, HistoryPage, user-input and audit/provenance boundaries. `Event.completeness` describes truncation of that live event payload itself; clients must not infer event-payload completeness only from a nested model or a later RESET.
- User input: questions, options and answers are structured and keyed by stable IDs. `RespondUserInputRequest.answers` is authoritative.
- Approval: resolved approvals preserve `resolved_decision`, including the distinction between ALLOW and ALLOW_FOR_SESSION.
- RenameCodex: Host-only display-title mutation, valid in every management state. It persists `manual_title_override`, emits CodexUpdated, and prevents later native automatic-title updates across restart.
- ForgetCodex: Host-only record deletion, valid only for `UNMANAGED`; every other management state returns `ERROR_CODE_CONFLICT`. It emits CodexForgotten, removes Host mapping/CurrentView/list-title/workspace registration, retains native rollout/CWD/audit/dedup state, and never reuses an ID. The Host persists a forgotten candidate and discovery merges it with runtime results as `RESUMABLE` with no `managed_codex_id`. A materialized session reimports under a new ID while retaining the same native thread/history. During the same run an unmaterialized session reuses its old thread and `StartTurn` materializes it without a fabricated rollout; after a restart, a genuine upstream thread-not-found result creates a new native thread in the stored CWD.
- Rename: renamed file changes carry both `old_path` and `new_path`; `path` is a display/compatibility primary path.
- Provenance: item/turn snapshots carry a provenance kind, and diagnostic `AuditRecord` can carry typed `Provenance` plus `CanonicalActivity`, linking imported history, live wire, or Host-synthesized facts to source record IDs.
- Watch restart: a cursor is the pair `(after_host_run_id, after_event_seq)`. A request carrying `after_event_seq` must also carry the `ServerHello.host_run_id` that produced it; a missing run ID is `ERROR_CODE_INVALID_REQUEST`. A different run ID always produces `WATCH_MODE_RESET` plus `CurrentView` and `WATCH_RESET_REASON_HOST_RESTARTED`. A matching run ID follows same-run replay availability.
- Runtime restart: planned restart is allowed only without an active turn. V1 does not hot-recover an active turn or blindly replay `IN_PROGRESS`/unknown-result side effects.
- Audit: human-readable diagnostic evidence, not a compliance or tamper-proof log; no hash chain or per-record forced fsync requirement.

The authoritative `.proto` files and generated artifacts are changed and released together in the public protocol repository. The Host consumes the pinned release and does not regenerate protocol code locally.

## Deterministic behavior required by implementations

- Side-effect dedup covers 12 RPCs: CreateCodex, ImportSession, StartTurn, InterruptTurn, RespondApproval, RespondUserInput, UnmanageCodex, RenameCodex, ForgetCodex, WriteWorkspaceTextFile, UploadWorkspaceEntry, and UploadImageAttachment. It compares a canonical fingerprint of the complete normalized operation payload, not only operation type/target. A reused ID with a different fingerprint returns `ERROR_CODE_CONFLICT`. Terminal success and error responses may be replayed; an `IN_PROGRESS`/unknown-result record is never blindly executed again after restart. The current lightweight marker is persisted before dispatch and completion after Backend success; a Host crash after app-server acceptance but before Host finalization remains outcome unknown and is never automatically replayed rather than claiming exactly-once recovery.
- Same-Codex side-effect operations assume sequential submission by one client. Concurrent mutations from multiple clients are not supported by this Demo.
- A request whose deadline is already expired is rejected before dispatch. Once a side effect or turn has been submitted, only its single terminal Response is sent; deadline never implies `InterruptTurn` and never produces a second Response.
- A Watch Response is sent before replay/live Events. Rewatching the same Codex on one connection replaces that watch. RESET response head equals `reset_view.head_event_seq`; a matching-run cursor RESUMED replays `(after_event_seq, head_event_seq]` then live events.
- `chunk_seq` starts at 1 and is independent/contiguous per item across all delta variants. Duplicate chunks are ignored; a gap requires a Watch RESET. `ItemUpdated` is a complete item upsert, not a field merge.
- Response and causally related Event may arrive in either order; clients correlate using `caused_by_request_id` and must not infer success only from arrival order.
- `page_size=0` uses the Host default; values above the advertised maximum are clamped. Tokens are opaque and bound to the operation plus normalized query; malformed or mismatched tokens return `ERROR_CODE_INVALID_REQUEST`.
- Forgotten candidates are merged only into the terminal runtime-discovery page. Its cursor does not cover that persisted source, so the terminal response can exceed `page_size`; no composite cursor is implemented for this Demo.
- `ImportSessionRequest.source` plus `session_id` identify a candidate; session IDs need not be globally unique across sources.
- Before ClientHello, any application Frame is invalid. Missing/wrong WebSocket subprotocol is rejected during upgrade. Duplicate hello, empty oneof, unknown fields/enums, binary messages, noncanonical 64-bit JSON representation, or oversized messages are protocol errors.
